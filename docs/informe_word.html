1. DESCRIPCIÓN DE LA ACTIVIDAD

El presente informe documenta el proceso técnico de configuración, endurecimiento de seguridad y despliegue en producción del Producto Mínimo Viable (MVP) AURA Smart Parking en la nube pública de Microsoft Azure, ejecutándose sobre el sistema operativo Windows Server 2022 Datacenter administrado mediante el servidor web Internet Information Services (IIS).

El proyecto aborda la problemática de congestión y búsqueda ineficiente de aparcamiento en zonas urbanas densas, articulando una solución integral que vincula una maqueta física a escala (70 × 72 cm) controlada por un microcontrolador Arduino UNO R3 con una plataforma web en la nube que gestiona reservas, detección automática vehicular mediante ultrasonido, control de barreras de acceso y tarificación en pesos chilenos ($ CLP).

2. MÁQUINA VIRTUAL EN MICROSOFT AZURE

Para garantizar el aislamiento de procesos y el control exhaustivo sobre el servidor web, los puertos de red y el runtime de ejecución, se aprovisionó una máquina virtual bajo el modelo IaaS (Infraestructura como Servicio) en Microsoft Azure.

2.1 Parámetros y Características del Recurso Cloud

  • Nombre del Recurso: vm-aurasmartparking-prod
  • Grupo de Recursos (Resource Group): rg-smartparking-ipst
  • Región Cloud: Chile Central (Santiago de Chile)
  • Sistema Operativo: Windows Server 2022 Datacenter: Azure Edition - Gen2 (x64)
  • Tamaño de Instancia (SKU): Standard_B2s (2 vCPUs virtuales, 4 GiB de memoria RAM, hasta 3200 IOPS de rendimiento en disco)
  • Almacenamiento del SO: Disco SSD Premium de 128 GiB administrado por Azure con cifrado en reposo (PMK)
  • Zona de Disponibilidad: Zona 1 con acuerdo de nivel de servicio (SLA) del 99.99%
  • Tipo de Seguridad: Estándar con arranque seguro y compatibilidad con vTPM

4. WINDOWS SERVER E INSTALACIÓN DE IIS

4.1 Conexión por Escritorio Remoto (RDP)

El acceso al entorno de administración se realizó mediante el cliente nativo de Escritorio Remoto de Windows: 

mstsc /v:68.211.136.184:3389

Iniciando sesión con la cuenta de administrador aprovisionada en Azure.

4.2 Instalación del Rol Web Server (IIS) mediante PowerShell

Para automatizar el despliegue y evitar inconsistencias manuales, el rol de IIS se instaló ejecutando el siguiente comando en la consola de PowerShell con privilegios elevados: 

Install-WindowsFeature -name Web-Server -IncludeManagementTools

Posteriormente, se verificó el arranque automático del servicio mediante: 

Get-Service -Name W3SVC | Select-Object Name, Status, StartType

4.3 Configuración del Sitio Web y Proxy Inverso

  1. Ruta Física: Se desplegó la aplicación en el directorio C:\inetpub\wwwroot\smart-parking, conteniendo la compilación optimizada del frontend de React y el backend Express.
  2. URL Rewrite y Application Request Routing (ARR): Se instalaron los módulos oficiales de IIS para enrutar las peticiones web de la SPA y redirigir las solicitudes a /api/* hacia el servicio interno de Node.js en el puerto 3001.
  3. Bindings (Enlaces): Configurado para escuchar en el puerto HTTP 80 para todas las IPs no asignadas bajo el nombre de host puntoalerce.chilecentral.cloudapp.azure.com.

7. EVIDENCIA DE LAS OPERACIONES CRUD

El flujo operativo del estacionamiento implementa las cuatro operaciones fundamentales del modelo CRUD:

7.1 CREATE (Crear Reserva de Espacio)

Descripción: Un usuario selecciona un cupo libre (ej. E-01), digita la patente del vehículo (CL-2026), el nombre del conductor y el tiempo estimado. El backend procesa la petición en POST /api/parking/reserve, cambia el estado a RESERVADO y genera un comprobante con código QR y código de reserva único.

[PEGAR AQUÍ CAPTURA 6: Formulario de reserva con patente chilena ingresada y el pase digital generado con código QR]
Figura 6: Evidencia de la operación CREATE: registro de reserva y emisión del pase de acceso digital con código QR.

7.2 READ (Consultar Estado de Cupos y Telemetría)

Descripción: La aplicación lee de forma periódica cada 2.5 segundos el estado de los 6 espacios de estacionamiento a través de GET /api/parking/state, actualizando los contadores de cupos libres (4 / 6), la réplica del display LCD 16x2 y la tabla de auditoría en tiempo real.

[PEGAR AQUÍ CAPTURA 7: Vista de los 6 espacios de estacionamiento y el tablero analítico con el conteo de cupos libres y ocupados]
Figura 7: Evidencia de la operación READ: consulta en tiempo real del estado de ocupación y distancias en centímetros de los sensores.

7.3 UPDATE (Actualización de Estado de Ocupación y Barreras)

Descripción: Cuando el sensor ultrasónico HC-SR04 de la maqueta física detecta un automóvil a menos de 10 cm (ej. 6.4 cm), el sistema ejecuta POST /api/parking/telemetry, actualizando el estado de LIBRE a OCUPADO, encendiendo el LED rojo físico y dibujando el vehículo adentro. Asimismo, la orden POST /api/parking/barrier rota el servomotor SG90 a 90° para abrir la barrera.

[PEGAR AQUÍ CAPTURA 8: Espacio E-02 en estado OCUPADO con el auto deportivo vectorizado y distancia de 6.4 cm]
Figura 8: Evidencia de la operación UPDATE: actualización dinámica de ocupación tras la lectura del sensor ultrasónico y apertura de barrera.

7.4 DELETE (Liberación de Cupo y Checkout)

Descripción: Cuando un vehículo abandona el estacionamiento, el operador pulsa "Retirar Auto / Cobrar" o el sensor de salida registra el paso. Se envía POST /api/parking/release, calculando la tarifa final por minuto transcurrido ($35 CLP/min), eliminando la asignación de la patente y restableciendo el espacio a LIBRE.

[PEGAR AQUÍ CAPTURA 9: Confirmación de liberación del espacio con desglose del cobro final y espacio volviendo al estado 'LIBRE']
Figura 9: Evidencia de la operación DELETE: checkout vehicular, cobro de tarifa calculada y liberación del cupo en el sistema.
